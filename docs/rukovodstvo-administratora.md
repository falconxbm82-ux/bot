# Руководство администратора Windows

DockBot ставится на Windows как процесс Python из venv. Служба регистрируется через NSSM. Хранилище — PostgreSQL. Резервная копия — ежедневный `pg_dump` в Планировщике заданий.

Площадка приёмки: Windows Server 2019/2022 или Windows 10/11 Pro 64-bit, от 2 ядер x86-64 и 2,0 ГГц, от 4 ГБ памяти, от 30 ГБ свободно на SSD, сеть от 100 Мбит/с, постоянный исходящий HTTPS. Скрипты NSSM и Планировщика на машине разработки не запускались: там не Windows.

Корень установки на стенде: `C:\Apps\DockBot`.

## Учётная запись и секреты

Файл `.env` лежит в корне установки и в git не входит. В нём задаются токен бота и строка подключения к базе. Пароль базы остаётся в этой строке и в переменной `PGPASSWORD` на время `pg_dump`. В командную строку `pg_dump` пароль не попадает. Токен бота, PIN пропуска и PIN персонала в журнал не пишутся.

Служба NSSM и задание Планировщика читают `.env` из корня установки. Учётная запись службы должна иметь право читать этот файл.

## PostgreSQL

Нужен PostgreSQL for Windows. Стендовое имя службы, от которой зависит DockBot: `postgresql-x64-16`. Это имя официального установщика PostgreSQL 16, не норма технического задания. Если служба называется иначе, передайте её имя параметром `-PostgresService` скрипта установки.

Пользователь базы — не суперпользователь. Пример строки без пароля:

```text
postgresql+psycopg://dockbot@127.0.0.1:5432/dockbot
```

Пароль дописывается в URL в `.env`. Базу и роль создаёт администратор СУБД. Схему создаёт сам процесс при старте.

## Виртуальное окружение

На машине нужен Python 3.12. Из корня поставки:

```text
py -3.12 -m venv C:\Apps\DockBot\.venv
C:\Apps\DockBot\.venv\Scripts\python.exe -m pip install -r C:\Apps\DockBot\requirements.txt
```

Скопируйте `.env.example` в `C:\Apps\DockBot\.env` и заполните `BOT_TOKEN` и `DATABASE_URL`. Остальные ключи описаны в примере.

Стендовые значения, которые имеет смысл записать в `.env`, пока заказчик не назвал свои:

- `WAREHOUSE_TIMEZONE=Europe/Moscow`
- `CANCEL_WINDOW_HOURS=2`
- сетка ворот: `GATES`, `GATE_WEEKDAYS`, `GATE_OPEN`, `GATE_CLOSE`, `SLOT_MINUTES`

`WAREHOUSE_LATITUDE` и `WAREHOUSE_LONGITUDE` оставьте пустыми, пока заказчик не даст точку склада. Без обеих координат служба напоминаний не стартует, опрос Telegram продолжается.

Персонал задаётся ключом `STAFF` в форме `роль:имя:PIN` или `роль:имя:PIN:telegram_id`. Роль — `security` или `warehouse`. PIN персонала на стенде — 6 цифр. Это не PIN пропуска. Значение PIN в репозиторий не кладут. Пустой `STAFF` уже записанных сотрудников не стирает.

Проверка вручную, без службы:

```text
cd /d C:\Apps\DockBot
.venv\Scripts\python.exe -m dockbot
```

Процесс применяет миграции, записывает сетку и персонал и начинает опрос Telegram.

## Служба NSSM

Второй способ службы не используется. Журнал событий Windows не пишется, пакет pywin32 не нужен.

Положите `nssm.exe` в `C:\Apps\DockBot\tools\nssm.exe`. От имени администратора:

```text
powershell -ExecutionPolicy Bypass -File C:\Apps\DockBot\windows\install-service.ps1
```

Скрипт создаёт каталоги `C:\Apps\DockBot\logs` и `C:\Apps\DockBot\backups`, регистрирует службу `DockBot` и запускает её. Программа службы — `C:\Apps\DockBot\.venv\Scripts\python.exe` с параметром `-m dockbot`, каталог приложения — `C:\Apps\DockBot`. Запуск автоматический. После сбоя служба перезапускается через 5 секунд. Служба зависит от `postgresql-x64-16`.

На ОС, которая не Windows, скрипт завершается до вызова `nssm`.

## Журнал

На Windows без `LOG_DIR` журнал пишется в `C:\Apps\DockBot\logs\dockbot.log`. Строка: время, уровень, имя, сообщение. Ротация на стенде: 10 МиБ и 10 архивов. NSSM дополнительно пишет `service-stdout.log` и `service-stderr.log` в тот же каталог и тоже поворачивает их. На другой ОС файл появляется только если задан `LOG_DIR`.

## Резервное копирование

Дампы лежат отдельно от журнала, в `C:\Apps\DockBot\backups`. Имя файла `dockbot-ГГГГММДД-ЧЧММСС.dump`. Хранится 14 копий, более старые удаляются после успешного дампа. Неуспешный `pg_dump` уже лежащие копии не удаляет.

Регистрация ежедневного задания на 02:00, от имени SYSTEM:

```text
powershell -ExecutionPolicy Bypass -File C:\Apps\DockBot\windows\register-backup.ps1
```

Задание называется `DockBotBackup` и запускает `python -m dockbot.backup` из корня установки. Время 02:00 и срок хранения 14 копий — стендовые. На ОС, которая не Windows, скрипт завершается до вызова `schtasks`. Ручной запуск той же команды на машине с PostgreSQL проверяет сам дамп, без Планировщика.
