# DockBot

Автоматизированная система управления очередью и бронирования окон разгрузки склада.
Интерфейс — Telegram-бот. Хранилище — PostgreSQL.

Приёмка по ТЗ рассчитана на Windows, PostgreSQL и venv. Разработка на другой ОС допустима.
Docker средой исполнения не является.

## Что уже запускается

Процесс `python -m dockbot`:

- читает окружение из `.env` и переменных среды;
- применяет миграции PostgreSQL и, если сетка задана в окружении, записывает её в базу;
- запускает long polling aiogram 3;
- на `/start` показывает меню водителя: «Забронировать» и «Мои брони»;
- ведёт мастер: дата, ворота, свободный слот, госномер, марка, ФИО, груз, сводка;
- по «Записать» в одной транзакции создаёт бронь и присылает QR и PIN;
- показывает будущие брони этого чата, пропуск, перенос и отмену внутри окна из настроек;
- для привязанного Telegram ID охраны или кладовщика добавляет меню смены;
- по `/staff` пускает сотрудника по PIN персонала (это не PIN пропуска) и привязывает пустой Telegram ID, не затирая чужой;
- на КПП читает QR пропуска через OpenCV или PIN пропуска и показывает карточку;
- ставит «Прибыл», «На воротах №X» и «Разгружен» только по допустимой цепочке;
- показывает смену текущих суток: время, ворота, госномер, ФИО, статус;
- если заданы пояс, окно отмены и геометка, в том же процессе запускает APScheduler:
  напоминания за 24 часа, 2 часа и 30 минут с точкой склада, подтверждение в T−2 ч
  и автоматическое «Опоздал» через 15 минут без отметки КПП.

`/cancel` сбрасывает незаконченный диалог и не оставляет бронь. Две машины на одни ворота и время не записываются: это держит ограничение базы. Охрана и кладовщик в этом срезе видят один и тот же модуль.

Пока заказчик не назвал значения, стенд плана использует пояс `Europe/Moscow` и окно отмены `2` часа. Это не норма ТЗ. Координаты склада в ТЗ не заданы. Горизонт выбора даты в ТЗ не задан; бот показывает 14 дней.

## Чего ещё нет

Служба NSSM, каталог логов Windows и задания резервного копирования. Координаты склада в ТЗ не заданы: пока широта и долгота пустые, напоминания не стартуют, а бот продолжает опрос. Более жёсткое разделение кнопок охраны и кладовщика по-прежнему не включено.

## Запуск

Нужны Python 3.12 и PostgreSQL. Пользователь базы — не суперпользователь.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` заполняются `BOT_TOKEN` и `DATABASE_URL`. Файл `.env` в поставку и в git не входит.
Пример строки подключения без секрета:

```text
postgresql+psycopg://dockbot@127.0.0.1:5432/dockbot
```

Часовой пояс, широта, долгота, окно отмены и сетка ворот могут остаться пустыми: опрос Telegram от этого не останавливается.
Без пояса, окна отмены и сетки мастер скажет, что склад не настроен. Пустая геометка не даёт запустить службу напоминаний (`Settings.require_site`). Такой службы в процессе пока нет. Координаты в строке настроек могут быть пустыми, пока их нет.

Пока заказчик не назвал значения, стенд плана использует пояс `Europe/Moscow` и окно отмены `2` часа. Это не норма ТЗ. Координаты склада в ТЗ не заданы.

Команду запускать из корня репозитория:

```bash
.venv/bin/python -m dockbot
```

Схему отдельно можно накатить так:

```bash
.venv/bin/alembic upgrade head
```
