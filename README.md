# DockBot

Автоматизированная система управления очередью и бронирования окон разгрузки склада.
Интерфейс — Telegram-бот. Хранилище — PostgreSQL.

Этот репозиторий — первый рабочий срез: каркас процесса, конфигурация и схема базы.
Приёмка по ТЗ рассчитана на Windows, PostgreSQL и venv. Разработка на другой ОС допустима.
Docker средой исполнения не является.

## Что уже запускается

Процесс `python -m dockbot`:

- читает окружение из `.env` и переменных среды;
- применяет миграции PostgreSQL;
- проверяет соединение с базой;
- запускает long polling aiogram 3;
- на `/start` показывает меню водителя: «Забронировать» и «Мои брони».

Кнопки меню пока только отвечают, что соответствующий шаг ещё не подключён.

## Чего в этом срезе нет

Мастер бронирования, запрет двойной записи в диалоге, QR и PIN, роли охраны и кладовщика, экран смены, статусы рейса, напоминания и опоздания (APScheduler), распознавание OpenCV, служба NSSM, каталог логов Windows и задания резервного копирования.

## Запуск

Нужны Python 3.12 и PostgreSQL. Пользователь базы — не суперпользователь.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` заполняются `BOT_TOKEN` и `DATABASE_URL`. Файл `.env` в поставку и в git не входит.
Пример строки подключения без секрета:

```text
postgresql+psycopg://dockbot@127.0.0.1:5432/dockbot
```

Часовой пояс, широта, долгота и окно отмены могут остаться пустыми: опрос Telegram от этого не останавливается.
Пустая геометка, пояс или окно отмены не дадут запустить службу напоминаний (`Settings.require_site`). Такой службы в процессе пока нет.

Пока заказчик не назвал значения, стенд плана использует пояс `Europe/Moscow` и окно отмены `2` часа. Это не норма ТЗ. Координаты склада в ТЗ не заданы.

Команду запускать из корня репозитория:

```bash
.venv/bin/python -m dockbot
```

Схему отдельно можно накатить так:

```bash
.venv/bin/alembic upgrade head
```
