# DockBot

Автоматизированная система управления очередью и бронирования окон разгрузки склада.
Интерфейс — Telegram-бот. Хранилище — PostgreSQL.

Приёмка по ТЗ рассчитана на Windows, PostgreSQL и venv. Разработка на другой ОС допустима.
Docker средой исполнения не является.

## Что уже запускается

Процесс `python -m dockbot`:

- читает окружение из `.env` и переменных среды;
- применяет миграции PostgreSQL и, если сетка задана в окружении, записывает её в базу;
- запускает long polling aiogram 3;
- держит под полем ввода клавиатуру с ролями «Водитель», «Охрана» и «Кладовщик»;
- у водителя на ней же «Записаться», «Мои брони», «Мой пропуск», «Как проехать», «Отменить», «Перенести» и «Помощь»; «Водитель» снимает привязку персонала;
- ведёт мастер: дата, ворота, свободный слот, госномер, марка, ФИО, груз, сводка;
- по «Записать» в одной транзакции создаёт бронь и присылает QR и PIN;
- показывает будущие брони этого чата, пропуск, перенос и отмену внутри окна из настроек;
- после верного PIN охраны показывает «Сканировать QR», «Ввести PIN» и «Смена сегодня»; после PIN кладовщика — монитор смены и фильтры; неверный PIN роль не меняет;
- по `/staff` пускает сотрудника по PIN персонала (это не PIN пропуска) и привязывает пустой Telegram ID, не затирая чужой;
- охрана на КПП читает QR пропуска через OpenCV или PIN пропуска и ставит «Прибыл»;
- кладовщик видит смену текущих суток и ставит «На воротах №X» и «Разгружен» только по допустимой цепочке;
- чужую отметку сервер отклоняет, даже если кнопка пришла из старого сообщения;
- если заданы пояс, окно отмены и геометка, в том же процессе запускает APScheduler:
  напоминания за 24 часа, 2 часа и 30 минут с точкой склада, подтверждение в T−2 ч
  и автоматическое «Опоздал» через 15 минут без отметки КПП;
- пишет журнал: на Windows в `C:\Apps\DockBot\logs`, на другой ОС — в каталог из `LOG_DIR`, если он задан.

`/cancel` сбрасывает незаконченный диалог и не оставляет бронь. Две машины на одни ворота и время не записываются: это держит ограничение базы. Охрана отмечает прибытие. Кладовщик ведёт ворота и разгрузку.

## Стендовые значения

Эти числа выбраны для стенда. В ТЗ их нет:

- часовой пояс `Europe/Moscow`;
- окно отмены и переноса `2` часа;
- PIN персонала — `6` цифр;
- копия `pg_dump` раз в сутки, хранить `14` дампов;
- журнал: строки `время уровень имя сообщение`, ротация `10` МиБ и `10` архивов;
- пауза NSSM перед повторным запуском `5` секунд;
- служба PostgreSQL, от которой зависит DockBot, `postgresql-x64-16`;
- время задания копии `02:00`.

Координаты склада не выдуманы и остаются пустыми. Горизонт выбора даты в ТЗ не задан; бот показывает 14 дней.

## Служба и копия

`windows/install-service.ps1` ставит и запускает службу только через NSSM: Python из venv, автозапуск, перезапуск после сбоя, зависимость от PostgreSQL. Журнал событий Windows не используется, pywin32 не входит в зависимости. `windows/register-backup.ps1` регистрирует ежедневное задание Планировщика на `python -m dockbot.backup`. Пароль базы остаётся в `PGPASSWORD` процесса и в аргументы `pg_dump` не попадает. Учётная запись службы читает `.env` из корня установки. Эти скрипты рассчитаны на Windows и на другой ОС до NSSM и Планировщика не доходят.

## Запуск

Нужны Python 3.12 и PostgreSQL. Пользователь базы — не суперпользователь.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` заполняются `BOT_TOKEN` и `DATABASE_URL`. Файл `.env` в поставку и в git не входит.
Пример строки подключения без секрета:

```text
postgresql+psycopg://dockbot@127.0.0.1:5432/dockbot
```

Часовой пояс, широта, долгота, окно отмены и сетка ворот могут остаться пустыми: опрос Telegram от этого не останавливается.
Без пояса, окна отмены и сетки мастер скажет, что склад не настроен. Пустая геометка не даёт запустить службу напоминаний (`Settings.require_site`). Координаты остаются пустыми, пока заказчик их не назовёт. Стендовые пояс, окно отмены и длина PIN персонала перечислены выше. На Windows без `LOG_DIR` журнал идёт в `C:\Apps\DockBot\logs`. На другой ОС файл журнала появляется только если задать `LOG_DIR`.

Команду запускать из корня репозитория:

```bash
.venv/bin/python -m dockbot
```

Схему отдельно можно накатить так:

```bash
.venv/bin/alembic upgrade head
```
